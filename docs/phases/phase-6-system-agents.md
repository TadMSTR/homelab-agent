# Phase 6 — System Agents

**Completed:** 2026-04-03

Phase 6 deployed three system agents — autonomous, scheduled, headless — that maintain the platform without operator intervention. Each agent runs as its own Unix user, has team-scoped NATS ACLs, AppArmor enforce profiles, and restricted sudoers access. The Owner's Manual site (docs.helmforge.me) provides auto-generated platform documentation served via mkdocs + SWAG + Authentik.

## What Was Built

### System Agents

Three system agent "teams" deployed, each with a golden master CLAUDE.md at `/opt/helm/agents/<type>/`:

| Agent | Team | Tier | Schedule | Role |
|-------|------|------|----------|------|
| security | The Watch | resident | Every 6h | CISA KEV checks, AppArmor violation review, NATS ACL denial review, Docker health, credential rotation verification. **Read-only — never modifies infrastructure.** |
| update | The Engineers | burst | Saturday 03:00 | OS patches, Docker image pulls, PM2 updates. Staged execution with pre-checks, btrfs snapshots, and automatic rollback on health check failure. |
| docs | The Archivists | resident | Daily 05:00 | Regenerates Owner's Manual sections from live system state. Commits to `helm-owners-manual` repo. Event-triggered for real-time updates. |

### helm-launch v3 — Headless Mode

`helm-launch` gained a `--headless` flag for unattended execution:

```bash
helm-launch <agent-type> --headless "<task description>"
```

Headless mode:
1. Creates an ephemeral working directory via `create-ephemeral-clone.sh` — symlinks CLAUDE.md from the golden master at `/opt/helm/agents/<type>/`
2. Chowns the ephemeral dir to the agent user
3. Launches with `claude -p "<task>" --dangerously-skip-permissions`
4. Sets `--wait` on `systemd-run` so helm-launch blocks until completion
5. Cleans up the ephemeral directory on exit (trap)

Interactive mode (v2) continues to work unchanged.

### Owner's Manual

Git repo: `~/repos/personal/helm-owners-manual/`
Served at: `docs.helmforge.me` (SWAG + Authentik forward auth)
Tool: mkdocs with Material theme (installed via pipx)
Sections: 10 markdown files under `docs/` — system-specs, docker-stacks, agent-inventory, network, backup-status, secrets-inventory, pm2-services, update-history, security-posture, troubleshooting (manual).

Auto-generated sections use `<!-- AUTO-GENERATED — DO NOT EDIT -->` headers. The docs agent reads live system state (Docker API, manifests, PM2, SWAG confs, AppArmor, btrfs) and rewrites each section from scratch — no patch-based updates.

### Unix Users (3 new)

| User | Shell | Home | Groups |
|------|-------|------|--------|
| `helm-security` | `/usr/sbin/nologin` | `/home/helm-security` | `helm-security` |

All agent homes are 700, owned by the agent user. Loginctl linger enabled.

### Sudoers

Each agent type has a dedicated sudoers file under `/etc/sudoers.d/`:

- **`helm-security`** — No sudo access (intentionally empty file documenting this). Read-only monitoring only.
- **`helm-update`** — All privileged operations go through `update-agent-wrapper.sh`, which validates stack names, PM2 process names, and btrfs snapshot destinations. Direct sudo only for `apt-get update/upgrade/dist-upgrade`, read-only `docker ps`, and `systemctl is-active`.
- **`helm-docs`** — Read-only: `ufw status`, `aa-status`, `btrfs subvolume list`, `lsblk`.
- **`helm-agent-launch`** — Extended to allow `ted` to run `claude` as `helm-security`, `helm-update`, and `helm-docs`.

### AppArmor

Three new profiles generated by `gen-apparmor-profile.py` (rewritten in Phase 6 security audit):
- `helm-security` — enforce mode, per-binary allowlist (base + `curl`, `jq`, `diff`, `sha256sum`), broad `/opt/appdata/` read (justified for audit)
- `helm-update` — enforce mode, per-binary allowlist (base + `apt-get`, `docker`, `btrfs`, `systemctl`, `pm2`), no appdata read
- `helm-docs` — enforce mode, per-binary allowlist (base + `lscpu`, `free`, `lsblk`, `ip`, `ufw`, `aa-status`, `pm2`, `mkdocs`), appdata scoped to SWAG proxy confs only

Phase 6 security audit replaced the `/usr/bin/** rix` wildcards from Phase 5 with explicit per-agent binary lists.

### Credential Rotation

`rotate-nats-creds.sh` extended to cover `helm-security`, `helm-update`, and `helm-docs` (6 total agent users rotated). `helm-build` remains excluded (operator-initiated burst agent; rotating mid-build would break the session).

## Security Audit

14 findings (0 critical, 3 high, 5 medium, 4 low, 2 info). All resolved:
- H-01/H-02/L-03: Sudoers wildcards replaced with validated `update-agent-wrapper.sh`
- H-03: AppArmor `/usr/bin/** rix` replaced with per-agent binary allowlists
- M-01: `/opt/appdata/` read access scoped per agent
- M-02: Docs agent NATS subscribe narrowed from `events.>` to specific subjects
- M-03: Ephemeral session ownership fixed, cleanup cron added
- M-04: `parse-manifest.py` default `ted` user removed — `unix_user` now required
- Accepted risks: shared API key (M-05), helm-build cred not rotated (L-02), /home/ted/ 701 (L-04), security agent full subscribe (I-01), `--dangerously-skip-permissions` in headless mode (I-02)

Full report: `~/repos/audits/security-audits/helm-phase6-system-agents/report.md`
